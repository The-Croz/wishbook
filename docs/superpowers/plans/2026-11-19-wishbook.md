# Wishbook Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A self-hosted, phone-first PWA where the Crosby family shares Christmas wishlists, adds gifts by pasting links, and claims gifts without the recipient ever seeing claims.

**Architecture:** One SvelteKit app (Node adapter) with server-side rendering and form actions, SQLite via Drizzle on a mounted `/data` volume, in-process nightly price refresh with `node-cron`. All claim secrecy lives in one server module (`src/lib/server/visibility.ts`) that every loader and endpoint passes data through; the client never receives claim data it may not show.

**Tech Stack:** SvelteKit 2 + Svelte 5, TypeScript, `@sveltejs/adapter-node`, `better-sqlite3` + `drizzle-orm` + `drizzle-kit`, `@node-rs/argon2`, `cheerio`, `node-cron`, Vitest, Playwright (smoke only), Docker (`node:22-alpine`).

**Spec:** `PRODUCT.md` (product truth) and `design/mockups.html` + `design/brand/` (screens, logo, icons). `.impeccable/surfaces/design-mockups-html.md` holds the visual direction contract.

## Global Constraints

- App title everywhere (manifest `name`/`short_name`, `<title>`, header): **Wishbook**. Logo text reads **Crosby Family**, never just "Crosby".
- The owner of a list never sees claim status for that list: not in HTML, JSON, form-action results, counts, progress bars, or the "I'm getting" page. Enforced server-side.
- Managers of a managed kid's list DO see claims on it. Managed kids have no password and cannot log in.
- Only the owner or a managing parent may create, edit, delete, prioritise, or mark received on a list's items. Everyone else may only claim/unclaim.
- No public sign-up. Accounts are created by an admin. First admin is seeded from env `ADMIN_USERNAME` / `ADMIN_PASSWORD` when the users table is empty.
- Price refresh runs nightly at `0 3 * * *` server local time; every price shows "checked <relative time>". A failed fetch keeps the last known price and never overwrites title/image/price with blank or captcha-page data.
- Single container, data at `/data/wishbook.db`, listens on `PORT` (default `3000`), `ORIGIN` env required (reverse proxy terminates TLS). Session cookie: `HttpOnly`, `Secure`, `SameSite=Lax`, 30-day sliding expiry.
- Palette tokens: red `#C8102E`, red-deep `#9A0C23`, ink `#1A1A1A`, mustard `#F2B705`, pine `#2E7D5B`, wash `#F4F2EE`, rule `#E4E1DA`, muted `#5C5A55`. Fonts: Archivo Black (display), Atkinson Hyperlegible (body), Caveat 700 (claim handwriting only), self-hosted under `static/fonts/`.
- Minimum body text 15px, tap targets ≥ 44px, WCAG AA contrast.
- Money stored as integer cents plus ISO currency code; displayed with `Intl.NumberFormat('en-US', {style:'currency'})`.

## Review Focus

1. **Amazon returns a captcha / robot-check page** → scraper reports `blocked`, item keeps prior data, UI still adds the gift with what the user pasted (URL as title, editable). Tests in Tasks 6 and 7.
2. **Two people tap "I'll get this" at the same moment** → exactly one claim wins; the other sees "Kate already has this". Test in Task 5.
3. **Owner reaches claim data through a side door** (item detail URL, form action response, family-home counts, "I'm getting" list, received/archive view) → none of it leaks. Tests in Tasks 3, 4, 5, 9.
4. **Owner deletes or edits a gift someone already claimed** → the claimer sees it in "I'm getting" as "Removed from the list" (soft delete), not silent disappearance. Test in Task 5.
5. **Pasted text isn't a clean URL** (Amazon share text like "Check out this… https://a.co/d/abc", short links, trailing tracking params) → URL is extracted, redirects followed, canonical URL stored. Test in Task 6.

### Task 6: Link scraping

**Files:**
- Create: `src/lib/server/scrape/{index,extractUrl,generic,amazon}.ts`, `tests/unit/scrape.test.ts`, `tests/fixtures/{amazon-product,amazon-captcha,amazon-deal,og-shopify,jsonld-target,no-metadata}.html`

**Interfaces:**
- Produces:
  - `extractUrl(text: string): string | null`: first `https?://` URL in pasted text, trailing punctuation trimmed.
  - `canonicalize(url: string): string`: strips `utm_*`, `ref`, `tag`, `psc`, `th`; Amazon becomes `https://www.amazon.com/dp/<ASIN>`.
  - `type ScrapeResult = { status: 'ok' | 'blocked' | 'failed'; url: string; title?; imageUrl?; store?; priceCents?; listPriceCents?; currency? }`
  - `parseHtml(url: string, html: string): ScrapeResult` (pure; picks `amazon.ts` for amazon hosts, else `generic.ts`).
  - `scrape(rawText: string, fetchImpl = fetch): Promise<ScrapeResult>`: follows redirects (resolves `a.co`/`amzn.to`), 10 s timeout, browser-like `User-Agent` and `Accept-Language: en-US`, then `parseHtml`.
- Generic order: JSON-LD `Product` (`name`, `image`, `offers.price`, `offers.priceCurrency`) → OpenGraph (`og:title`, `og:image`, `product:price:amount`) → `<title>`. Store = `og:site_name` or hostname without `www.`, title-cased.
- Amazon: title `#productTitle`; price `.priceToPay .a-offscreen` then `#corePrice_feature_div .a-offscreen`; list price `.basisPrice .a-offscreen`; image `#landingImage[data-old-hires]` then `data-a-dynamic-image` largest key; `blocked` when page contains `captcha` form action or `api-services-support@amazon.com`.

- [ ] **Step 1: Failing tests** (fixtures saved from real pages, trimmed): Amazon product → title, `priceCents` 14999, `listPriceCents` 18999, image URL; captcha fixture → `status: 'blocked'` with no title; `extractUrl('Check out this deal https://a.co/d/3xYz9Q. Thanks')` → `https://a.co/d/3xYz9Q`; `canonicalize('https://www.amazon.com/Kindle/dp/B0D7HXJ8QK/ref=sr_1_3?tag=x&psc=1')` → `https://www.amazon.com/dp/B0D7HXJ8QK`; Shopify OG fixture → price from `product:price:amount`; JSON-LD fixture with `offers` array → lowest price; no-metadata page → `ok` with `<title>` only; `scrape` with a fetch that rejects → `failed`, never throws.
